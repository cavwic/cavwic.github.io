## 先问：输出错了，谁需要做什么

“希望 AI 处理公司的资料”可能指三件完全不同的事。知识问答要找出可引用的答案；字段提取要把原文变成可校验的结构；业务执行要改变另一个系统的状态。它们可以共用模型，但不能共用一套含糊的验收。

对问答，关键是证据能否找到、版本是否正确、无答案时能否停止。对提取，关键是字段位置、单位、缺失值和修订记录。对执行，关键是权限、审批、重复事件和写入回执。

## 用三个反例检查方案

**找到一段相似文字，不等于找到适用依据。** 同一个政策的旧版、草稿和生效版可能都包含关键词。RAG 的知识准备和检索控制要保留版本及权限，不能把相似度当授权或有效性。[Microsoft RAG 文档](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)

**输出合法 JSON，不等于字段正确。** 一个日期可能格式正确却属于签署日而非生效日。对关键字段，应保留原文定位、字段定义和人工核对入口。计算字段由程序重算，不凭模型口述。

**返回“已完成”，不等于目标系统已写入。** 必须保存可查询的目标记录标识及最终状态。目标超时时，先核对是否已完成，再决定是否重试。

## 一张更有用的选型对照表

| 要核对的问题 | 需要演示或提交的证据 |
| --- | --- |
| 数据如何授权与更新 | 角色隔离样本、增量更新与删除传播记录 |
| 输出怎么校验 | 字段契约、原文定位、业务规则及失败样本 |
| 模型是否可替换 | 固定测试集、版本记录和同口径复测结果 |
| 接口失败怎么办 | 超时、重复提交、部分成功和接管演练 |
| 成本怎么计算 | 每任务调用、重试、解析、存储及人工修订 |

## 我的判断

先选一个任务和一个授权数据域，做能被业务人员重复执行的测试，再决定是否扩展。不要因为平台拥有 Agent 或工作流画布，就假定它已经解决权限和异常。文档中的恶意指令也可能影响模型行为；提示词防护不能替代程序侧的权限控制。[OWASP 说明](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
