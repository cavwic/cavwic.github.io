## 观点

“让 Agent 自己完成”不是产品能力描述，而是一组权限承诺。读取客户资料、发邮件、改订单和删除记录，风险完全不同，不能共用一句“支持工具调用”。

每个动作应有单独的授权模型：谁可以发起，模型可以决定什么，规则校验什么，谁批准，执行后留下哪些日志，失败怎样补偿。只要其中一项答不上来，就不应开放自动写入。

有人会认为人工审批会削弱自动化价值。这个反例只在低风险、高频、规则稳定的任务上成立。对外承诺、资金、删除、敏感数据和不可逆操作，审批本身就是控制措施。更合理的演进顺序是先做只读建议，再做受控写入，最后才讨论限定范围内的自动执行。

实施时，工具清单要和权限矩阵放在一起。演示脚本也必须包含超时、重复提交、部分成功和返回状态不明。Agent 的专业感不来自动作多，而来自它知道什么时候不该继续。
