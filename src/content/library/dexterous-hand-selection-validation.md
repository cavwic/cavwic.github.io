## 先问：为什么不是夹爪

灵巧手不是自由度更多的夹爪。它带来更丰富的接触与手内操作能力，也带来更多驱动、传感、控制、标定、温升、线缆和维护问题。如果对象固定、姿态可控、节拍优先，专用夹具或电动夹爪往往更稳。

所以选型第一问不是“要多少自由度”，而是“目标任务中有哪些接触变化，简单末端为什么处理不了”。答不清这一点，后面的参数比较很容易失焦。

## 一：对象集是否代表真实任务

抓取测试必须有对象集。每个对象记录尺寸、质量、材质、表面摩擦、刚度、易损性、允许接触区域、初始姿态范围和验收容差。测试对象只挑规则硬物，会高估系统能力。

对象集应包含边界样本：最小、最大、最滑、最软、最易变形、最难定位，以及包装破损或摆放偏差。还应区分“成功拿起”和“完成任务”。能拿起杯子，不等于能在不遮挡目标区域的前提下稳定递交。

## 二：自由度、驱动数和耦合关系是什么

自由度描述可运动维度，驱动数描述独立控制能力，两者不应混为一个数字。欠驱动结构能用较少执行器实现包络抓取，但手指关节未必能独立到达任意姿态。对于遥操作、数据采集或精密手内操作，这种差异会直接影响任务空间。

评估时需要拿到关节拓扑、主动与耦合自由度、限位、传动方式和控制模式。没有这些信息，单看外形和自由度总数无法推断可控性。

## 三：力的口径能否对上任务

“握持力”“指尖力”“负载”常用不同姿态、方向和测量条件。比较前必须统一口径：是单指还是整手，是静态还是动态，是指尖法向力还是对象允许负载，腕部姿态和摩擦条件是什么。

目标不是追求最大力，而是在不损坏对象、不引发过热的前提下保持足够稳定。软物体、薄壁件和易碎物需要力控制或顺应；重物还要检查腕部和机械臂的力矩余量。

## 四：触觉数据是否真正可用

触觉不等于“有传感器”。至少要核对触觉覆盖区域、测量维度、量程、分辨率、采样率、迟滞、漂移、标定方法、数据接口和时间同步。厂商公开页面没有说明的字段，必须保留未知。

验证触觉时，不只测静态按压。还应测试接触定位、滑移、重复接触、温度变化、长时间零点漂移，以及多个指尖同时受力时的数据一致性。若控制算法只能获得处理后的事件而非原始数据，也要评估是否满足二次开发。

## 五：控制与集成是否进入同一时钟

灵巧手需要与机械臂、视觉、遥操作和任务系统协同。方案中应明确通信协议、控制频率、命令模式、状态反馈、时间戳、错误码、急停和断联行为。

很多演示问题不是抓取算法本身，而是坐标、时间和状态不一致：相机帧过期，手眼标定偏移，机械臂已经到位但手的状态仍滞后。联调计划应单独安排时间同步、坐标系、错误恢复和版本兼容测试。

## 六：温升、寿命和维护是否可接受

高集成度手指把电机、减速、传感和线缆压在有限空间内。连续抓取时的温升、降额策略、线缆弯折、齿轮或腱绳磨损，会比单次峰值性能更接近交付风险。

耐久测试必须说明动作、负载、速度、环境、周期和维护条件。“完成多少次循环”只有在测试工况一致时才可比较。还要记录易损件、校准工具、更换时间、备件交期和现场是否能自行维护。

## 建立一份可复测的抓取记录

每次测试至少记录以下字段：

| 类别 | 字段 |
| --- | --- |
| 对象 | 编号、尺寸、质量、材质、表面、初始姿态 |
| 配置 | 手型、固件、控制模式、抓取策略、力阈值 |
| 过程 | 接近、预形、接触、闭合、抬升、移动、放置 |
| 结果 | 成功、滑移、损伤、位姿误差、人工干预 |
| 性能 | 时间、温度、力、触觉、通信异常 |
| 复现 | 日志、视频、参数文件、测试人和日期 |

成功率应按对象和失败类型拆分。平均成功率会掩盖“某一类对象始终失败”的事实。权重可以透明调整，但未知参数不能默认按平均值补齐；它们应降低结论可信度并触发厂商询证或样机测试。

## 选型结论应是什么样

好的结论不是“某产品综合第一”，而是：在指定对象集、机械臂、控制方式和节拍下，候选 A 已有足够公开证据进入样机测试；候选 B 的触觉和接口仍需询证；候选 C 可用更简单末端替代。

这样的结论看起来没有排行榜干脆，却更接近采购、集成和验收真正需要的决策。
