## Position

Copying robot specifications into a table is not product selection. Payload without pose and speed, endurance without task duty cycle, and reach without collision and end-effector orientation cannot be compared.

Set common conditions first. A material-handling task needs object mass, center of mass, end tool, maximum extension, speed, route, and daily cycles. A navigation task needs map change, foot traffic, flooring, doors, elevators, and network conditions. Specifications answer the same question only when those conditions align.

Research or display procurement is a valid counterexample. The buyer may value developer access and budget without requiring production cycle time. That shows why comparison dimensions must change with the product category. One overall score cannot fit every robot.

The product matrices therefore retain "Not public." An unknown value does not become zero and is not filled with a class average. It triggers a vendor question or hardware test and reduces confidence in the current conclusion. An honest gap is more useful than a false ranking carried to two decimal places.
