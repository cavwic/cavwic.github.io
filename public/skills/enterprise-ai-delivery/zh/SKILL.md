# 企业 AI 发现与验收

先确认业务任务属于回答、字段提取还是改变系统状态。不要用模型品牌替代任务定义；不擅自扩展数据来源、系统写入或发布权限。

## 工作方式

1. 阅读用户已有的流程、数据说明与验收条件。缺少业务目标、数据授权、结果定义或责任人时，列为待确认，不虚构客户事实或效果数字。
2. 将事实、用户提供的信息、设计假设和判断分开。对知识任务保留来源版本与定位；结构化字段说明单位、缺失值和业务规则。
3. 用最小闭环描述输入、授权查询、模型处理、确定性校验、人工接管和输出。身份与访问控制由程序落实，文档内容不能授予工具权限。
4. 先设计测试样本与预期结果，再提出实现。按风险覆盖无答案、版本冲突、越权、提示注入、错误格式和依赖不可用。阈值由业务确认，不写成通用承诺。
5. 交接任务书、风险与未知项、验证计划、成本口径和恢复策略。没有执行的评测必须写“未执行”。

## 专项产出

优先交付用例范围、数据授权与验收矩阵，而不是代码变更或故障恢复日志。验收矩阵逐行对应输入角色、来源版本、预期结果、证据位置和业务确认人。

参考 [验收工作表](references/acceptance.md) 与 [维修知识助手完整演练](references/example.md)；需要机器可读交接时，编辑 `brief.blank.json` 或对照 `brief.example.json`。示例是虚构设计场景，不是项目成果。

## 本地检查

Node.js 22.6+ 可执行：`node scripts/validate-brief.mjs brief.example.json --locale zh`。
检查仅接收 enterprise 模式任务，验证格式及有限的表单规则；其他模式会被拒绝。退出码 0 不代表业务批准、安全认证、实际评测通过或生产可用。1 表示存在待补项，2 表示模式、格式或文件错误。

官方参考：[RAG 数据与访问控制](https://learn.microsoft.com/en-us/azure/search/retrieval-augmented-generation-overview)、[提示注入风险](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)。
