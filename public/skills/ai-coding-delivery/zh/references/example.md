# CSV 检查器：变更契约与验证交接

本例只演示怎样组织开发任务，不附已实现代码；所有验证状态均为“待执行”。实际文件路径、命令和框架必须从目标代码库读取，不能按本例虚构。

## 需求与变更契约

在已有网页中增加 CSV 导入、缺列与重复行检查、错误清单导出。原文件不修改，数据不上传，不更换框架；本地完成，不提交、推送或部署。

先确认必需列、重复的业务定义、编码与最大文件量。如果这些尚未定义，分别登记待确认，不自行把“整行相同”和“同一业务记录”当成同一规则。

## 实施切片

1. 阅读现有工作区差异、导入入口、存储逻辑与测试，标记用户已有修改。
2. 完成读取、校验、展示和导出的最小闭环，不写回源文件。
3. 增加空、错、取消与重复操作状态，再检查窄屏和键盘操作。
4. 审查范围、依赖变化及数据边界；按真实结果填写交接。

## 验证记录模板

| 场景 | 预期 | 实际状态 |
| --- | --- | --- |
| 正常文件 | 正确行数，无错误时有明确结果 | 待执行 |
| 空文件 | 明确提示，不产生旧结果残留 | 待执行 |
| 缺列 | 指明缺少的列，不继续错误解析 | 待执行 |
| 重复行 | 依据确认后的重复定义定位记录 | 待执行 |
| 取消选择 | 原状态保持一致，不当作导入成功 | 待执行 |
| 导出再打开 | 内容、编码与原始定位对应 | 待执行 |

## 中断交接

逐项填写改动文件、入口、已执行命令与退出状态、未执行原因、用户数据是否保留、仍在运行的服务和下一步。构建若因环境依赖失败，记录阻塞，不标成通过。回退仅覆盖本次明确改动，不能清空工作区或撤销用户已有工作。
